# ROKFOSS-Shield 무응답 절단

웹 포트로 들어오는 비정상 트래픽에 응답을 만들지 않고 연결만 끊는 기능이다.
두 부분으로 나뉜다.

1. 비정상 입력에 대한 자동 침묵 절단 (설정 불필요)
2. `drop_all` 지시어로 지정한 곳의 무조건 절단

## 왜 만들었나

인터넷에 공개된 웹 포트에는 브라우저만 오지 않는다. SMB 협상 패킷, RDP
연결 요청, 평문 포트로 오는 TLS ClientHello, 정체불명 바이너리가 같은
포트로 들어온다. nginx 는 이런 입력을 HTTP 로 파싱하려다 실패하고
`400 Bad Request` 를 돌려준다.

문제는 그 응답의 크기다. ROKFOSS 오류 페이지는 로고가 들어 있어 22KB 가
넘는다. 즉 SMB 패킷 하나를 보낸 스캐너에게 22KB 를 그대로 돌려주고 있었다.
대역폭 낭비이자 불필요한 정보 제공이다.

## 1. 비정상 입력 자동 절단

다음 상태는 응답을 만들지 않고 연결을 끊는다. 설정이 필요 없다.

| 상태 | 상황 |
|------|------|
| 400 | 요청줄 파싱 실패 — 바이너리 스캔, 프로토콜 오인 |
| 414 | URI 가 너무 김 |
| 495 | 클라이언트 인증서 오류 |
| 496 | 클라이언트 인증서 없음 |
| 497 | 평문 포트로 들어온 TLS |

**413(본문 초과)은 일부러 제외했다.** 용량을 넘겨 업로드하는 정상 사용자에게는
이유를 알려주어야 하기 때문이다. 그쪽은 종전대로 413 안내가 나간다.

404·403·500 등 정상 요청에 대한 오류도 종전대로 오류 페이지가 나간다.

## 2. `drop_all`

```nginx
drop_all on;
```

**문맥:** `http`, `server`, `location`
**기본값:** `off`

켜져 있는 곳으로 들어온 요청은 응답 없이 즉시 연결이 끊긴다.

```nginx
server {
    listen 80;

    location / {
        root /path/to/mirror;
    }

    # 우리가 제공하지 않는 서비스 탐색은 전부 끊는다
    location ~* ^/(mcp|sse|owa|autodiscover|developmentserver)(/|$) {
        drop_all on;
    }
}
```

서버 전체를 막을 수도 있다.

```nginx
# 알 수 없는 Host 로 들어오는 요청 전부 절단
server {
    listen 80 default_server;
    drop_all on;
}
```

### 동작 지점

`location` 이 확정된 직후, **본문을 읽기 전에** 끊는다. 따라서 본문이 아무리
커도 읽지 않는다. `return 444` 는 `client_max_body_size` 검사가 먼저 걸려서
큰 본문을 붙이면 413 오류 페이지가 나가는 우회가 가능했는데, `drop_all` 은
그보다 앞서므로 그 구멍이 없다.

## 로그

절단된 요청은 access log 에 상태 **999** 로 남는다.

```text
999 | GET | /mcp | 0
```

999 는 실제로 전송되는 HTTP 상태 코드가 아니다. 클라이언트는 아무 응답도
받지 못한다. 로그에서 "응답 없이 끊었다" 를 구분하기 위한 내부 값이며,
`$status` 로 조회된다.

`drop_all` 로 끊은 경우 error log 에 `info` 수준으로 경로도 남는다.

```text
dropped by drop_all: "/mcp?"
```

## 주의

- 디도스 대응 수단이 아니다. 응답 생성은 없애지만 TCP 핸드셰이크 비용은
  그대로 지불한다. 볼류메트릭 공격은 방화벽이나 상단 CDN 이 맡아야 한다.
- 침묵 절단은 디버깅을 어렵게 만든다. 정상 클라이언트가 잘못된 요청을 보내면
  400 대신 연결이 끊기므로 원인을 알기 어렵다. access log 의 999 를 확인해야
  한다.
- `drop_all` 은 상위 문맥에서 상속된다. `http` 수준에 켜면 모든 요청이
  끊기므로 주의한다.
